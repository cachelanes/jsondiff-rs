● Recommendation: Set Keys First

  After reviewing both feature plans and the current codebase, I recommend
  implementing Set Keys (--set-keys) before Exclude Paths (--ignore/--include).

  Reasoning
  ┌────────────┬───────────────────────────────┬───────────────────────────────┐
  │   Factor   │           Set Keys            │         Exclude Paths         │
  ├────────────┼───────────────────────────────┼───────────────────────────────┤
  │ Scope      │ Contained to array.rs +       │ Touches entire diff engine    │
  │            │ types.rs                      │                               │
  ├────────────┼───────────────────────────────┼───────────────────────────────┤
  │ Path       │ Introduces new path notation  │ Matches against existing      │
  │ impact     │ [id=1]                        │ paths                         │
  ├────────────┼───────────────────────────────┼───────────────────────────────┤
  │ Dependency │ Independent                   │ Depends on path format being  │
  │            │                               │ stable                        │
  └────────────┴───────────────────────────────┴───────────────────────────────┘
  Key Dependency Issue

  Set Keys changes how paths are represented:
  - Current: $.users[0].name (positional)
  - After Set Keys: $.users[id=1].name (key-based)

  If Exclude Paths is implemented first with pattern matching for
  $.users[*].name, it would later need modification to also handle
  $.users[id=*].name patterns when Set Keys is added.

  Implementation Order Benefits

  1. Set Keys first → establishes both path formats upfront
  2. Exclude Paths second → can be designed to work with both [0] and [id=1]
  style paths from day one, avoiding rework

  Scope Comparison

  Set Keys requires:
  - New PathSegment::KeyMatch(Vec<(String, Value)>) variant in types.rs:26-32
  - New diff_arrays_by_key() function in array.rs
  - CLI flag addition

  Exclude Paths requires:
  - Path pattern parser with wildcards (*, [*], **)
  - Path matching logic integrated into the diff engine
  - Precedence handling between ignore/include

  ---
  Let me know if you'd like to proceed with Set Keys, or if you prefer to tackle
   Exclude Paths first for other reasons.

  Key Observations

  1. Root arrays:
  - jq: . is root, .[] iterates elements
  - jd: [] (empty array) targets root
  - gron: json is root, json[0] is first element
  - JSONPath: $ is root, $[*] for all elements

  2. Array wildcards:
  - jq: .[] (iterator, not wildcard)
  - jd: No wildcard - uses explicit indices or set mode
  - JSONPath: [*] is standard wildcard

  3. Most common pattern:
  - Dot notation for object keys: .foo.bar
  - Bracket notation for array indices: [0], [1]
  - gron's json.foo[0].bar is the most familiar/JS-like
